PregaCare AI - Project Explanation

Is this an AI project?
Yes. PregaCare AI is a student prototype for maternal wellness monitoring. It includes a machine-learning model that classifies maternal-health risk from health measurements. It is not a general-purpose chatbot, and it does not currently use a large language model (LLM) or generative AI.

What the project currently does

1. Maternal risk classification
   - Trains a Random Forest classifier using the Maternal Health Risk Data Set.csv file.
   - Uses six inputs: age, systolic blood pressure, diastolic blood pressure, blood sugar (BS), body temperature, and heart rate.
   - Classifies measurements into low risk, mid risk, or high risk.
   - Returns the predicted class, the model's probability for that class, a general recommendation, and flags indicating whether a healthcare review may be needed.
   - Reports holdout accuracy and per-class recall through the model information endpoint.
   - The prediction is a research/demo result, not a diagnosis or a substitute for professional or emergency care.

2. Synthetic wellness sensor readings
   - Generates changing demo readings for five fictional patients.
   - Simulates heart rate, oxygen saturation (SpO2), stress, temperature, blood pressure, and accelerometer movement.
   - Generates readings with bounded, gradually changing values; certain demo patients have readings intentionally kept in unusual ranges to show dashboard alerts.
   - Can simulate a fall by creating a high accelerometer magnitude and checking it against a threshold.
   - These values are generated by software, not collected from real people or connected sensors.

3. Web dashboards
   - Provides a page listing five fictional patients and a separate dashboard for each.
   - Refreshes sensor readings about every three seconds.
   - Displays the readings and highlights values with color-coded wellness indicators.
   - Shows a fall alert when the simulated accelerometer reading exceeds its threshold.
   - Lets the user enter age and blood sugar; the dashboard combines those values with the simulated reading's blood pressure, temperature, and heart rate, then requests a risk classification from the Random Forest API.
   - Includes a button to turn the fall simulation on and off.

4. HTTP API
   - GET / returns a basic message confirming the backend is running.
   - GET /api/health returns a health-check status and timestamp.
   - GET /api/test returns a simple test response.
   - GET /api/patients lists the demo patients.
   - GET /api/readings returns a synthetic reading for the default patient; ?demo_fall=true forces a demo fall.
   - GET /api/patients/{patient_id}/readings returns a synthetic reading for a selected patient.
   - GET /api/risk/model returns model information, input features, classes, and evaluation metrics.
   - POST /api/risk/predict accepts the six measurements and returns a model classification and recommendation.
   - GET /dashboard and GET /dashboard/{patient_id} serve the patient selection and patient dashboard pages.
   - FastAPI also provides interactive API documentation at /docs.

How it is built
The backend is written in Python using FastAPI. Uvicorn runs the web server, and scikit-learn provides the Random Forest model. The model loads the supplied CSV dataset and trains when the model module is loaded.

What is not implemented yet
The README describes a future roadmap that includes real sensor input, a Raspberry Pi Pico W, a database, a retrieval-augmented generation (RAG) system, embeddings, a vector database, and LLM assistance. Those are not currently implemented. The knowledge-base and synthetic-data folders do not contain an active RAG/LLM feature.

Important limitations
This is a demonstration and research prototype. Its patient records and sensor readings are synthetic, and its machine-learning predictions may be inaccurate or unsuitable for clinical use. It does not diagnose disease, predict complications, replace a qualified healthcare professional, or provide emergency care. Do not use it to make medical decisions.
