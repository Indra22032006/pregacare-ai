# PregaCare AI

Maternal wellness monitoring & AI assistance platform — 3rd-year EXTC student
prototype.

⚠️ **This system does not diagnose disease, predict medical complications,
or replace a doctor.** All scores and labels (e.g. "AI Monitoring Score",
"Unusual Pattern") are demonstration outputs from synthetic data.

## Stage 1 — what's here

The backend provides:
- `main.py` — FastAPI app with health, patient, readings, risk, and dashboard routes
- `simulator/sensor_simulator.py` — bounded synthetic wellness readings and fall detection
- `ml/maternal_risk_model.py` — Random Forest classifier trained from the supplied maternal-health CSV when the module loads
- `data/maternal_health/` — dataset and source notes used by the classifier

There is no database, LLM, or RAG pipeline yet. The classifier estimates
dataset risk categories from six measurements; it does not predict future
clinical outcomes.

## Maternal risk prediction

The backend now trains a Random Forest from the Maternal Health Risk Data
referenced by the Kaggle notebook:
`https://www.kaggle.com/code/yasserhessein/classification-maternal-health-5-algorithms-ml`

The model uses `Age`, `SystolicBP`, `DiastolicBP`, `BS`, `BodyTemp`, and
`HeartRate` to classify `low risk`, `mid risk`, or `high risk`. Use:

```powershell
curl -X POST http://127.0.0.1:8000/api/risk/predict `
	-H "Content-Type: application/json" `
	-d '{"Age":25,"SystolicBP":130,"DiastolicBP":80,"BS":15,"BodyTemp":98,"HeartRate":86}'
```

`high risk` maps to `requires_medical_attention: true`; `mid risk` maps to
`could_require_medical_attention: true`. See `/api/risk/model` for features
and holdout metrics. This is a research prototype, not a diagnosis or a
replacement for a qualified healthcare professional or emergency care.

## Setup

### 1. Create and activate a virtual environment

**macOS / Linux:**
```bash
cd pregacare-ai/backend
python3 -m venv venv
source venv/bin/activate
```

**Windows (PowerShell):**
```powershell
cd pregacare-ai/backend
python -m venv venv
venv\Scripts\Activate.ps1
```

You'll know it worked because your terminal prompt will show `(venv)` at
the start of the line.

### 2. Install dependencies

```powershell
python -m pip install -r requirements.txt
```

### 3. Copy the environment file

```bash
cd ..
cp .env.example .env
```
(On Windows: `copy .env.example .env`)

## Running the backend

From inside `backend/`, with the venv active:

```powershell
python -m uvicorn main:app --reload
```

If you are running from the project root instead, use:

```powershell
python -m uvicorn backend.main:app --reload
```

You should see something like:

```
INFO:     Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)
INFO:     Started reloader process
INFO:     Application startup complete.
```

`--reload` means the server restarts automatically whenever you save a
code change — very useful while developing.

```

```

### Option B — Sensor dashboard

Open:

```
http://127.0.0.1:8000/dashboard
```

The dashboard refreshes synthetic heart rate, SpO2, stress, temperature,
blood pressure, and accelerometer values every three seconds. Use

## Common errors & fixes

| Error | Cause | Fix |
|---|---|---|
| `command not found: uvicorn` | Virtual env not activated, or deps not installed | Re-run `source venv/bin/activate` then `pip install -r requirements.txt` |
| `Address already in use` | Port 8000 already taken by another process | Run `uvicorn main:app --reload --port 8001` and use that port instead |
| `ModuleNotFoundError: No module named 'fastapi'` | Installed packages into the wrong Python / venv not active | Confirm `(venv)` is showing in your prompt, then reinstall |
| Browser shows "This site can't be reached" | Server isn't running, or wrong URL | Check the terminal for errors; confirm you used `http://127.0.0.1:8000` not `https://` |
